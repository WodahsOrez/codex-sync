## 浏览器页面处理规则

- 当任务涉及一个或一串 HTTP/HTTPS 页面地址，并且诊断、修改或验收确实需要启动浏览器时，无需等待用户再次提醒：主动通过 CDP 启动或连接 Google Chrome，并为当前任务创建一个独立的浏览器窗口。
- 专用窗口用于本次任务的页面操作、Console/Network/DOM 检查和交互验收；不要占用、跳转、刷新或关闭用户正在使用的浏览器窗口和标签页。
- 用户一次提供多个页面地址时，在该专用窗口中分别打开独立标签页或按顺序处理，保持页面与地址一一对应，避免在同一标签页反复跳转导致状态、日志或验证结果串页。
- 自动浏览器诊断或验收默认通过 CDP 启动或连接 Chrome，并为当前任务创建专用窗口；由 AI 自动准备，不要求用户事先手动开启调试端口。
- 使用固定、独立且持久化的调试用户数据目录（Windows 默认 `%LOCALAPPDATA%\Chrome-Codex-Debug`），保留业务网站登录状态供后续任务复用；不使用随机临时用户目录，不复制日常 Chrome 的 Cookie、令牌或凭据。优先连接该专用目录已运行的 CDP 实例，避免配置目录冲突。
- 调试端口仅供本机连接；启动后确认 CDP 可连接。不要为启用 CDP 关闭或重启用户日常 Chrome，不默认复用日常 Chrome 的默认用户数据目录。
- 专用窗口无需登录 Google/Chrome 账号。若业务页面要求登录或验证码，保留窗口并暂停，由用户在可见页面手动完成后继续，不读取、记录或复用敏感凭据，不绕过认证。
- 页面修改完成后，应在专用窗口中重新加载目标页面并执行与需求直接相关的实际交互验证；保存成功、接口返回 HTTP 200 或代码编译通过不能单独作为页面验收完成的依据。
- 只读诊断或普通页面验收不得真正执行会改变业务状态的审批、退回、转办、保存、提交、签名确认、密码重置等动作。需要真实提交时，必须已有明确授权和可用测试数据；签名密码、登录密码、验证码等敏感凭据只由用户在可见页面输入，AI 不读取、不记录、不复用。
- 任务结束时只处理本次任务自行创建的窗口或标签页，不关闭用户原有窗口；如保留窗口便于用户复查，应明确告知。

## DHR 个人本地运行约定

- 对来自 `git.gct-china.com/paas/frontend/gct-dhr-kit` 的 checkout（如 dhr-dev/dhr-test）及其分叉 worktree，需要本地启动、调试或浏览器验收时，先阅读 [dhr-local-dock 技能](C:/Users/yumoz/.codex/skills/dhr-local-dock/SKILL.md)，并按当前 cwd 的 Git 根目录复用或登记 Local Dock 服务。先核实 remote，不只按目录名判断。
- 这是用户的个人启动偏好：使用 Local Dock，业务仓库文档中的 Nginx/直接 dev 启动步骤作为旧方式；保留其静态检查和构建约定。用户本次明确指定其他方式时遵循用户。纯文档和不需运行的任务不自动起服务。
- 不使用主 checkout 的地址验证 worktree，不覆盖个人配置、不重启管理软件或影响其他仓库服务；浏览器仍遵守上面的专用窗口与登录规则。
